# AeroMart Semantic Search — Code Audit Report

**Reviewer perspective:** Senior data engineer reviewing the repository as an inherited, on-premise semantic-search pipeline.  
**Scope:** Every checklist item A-1 through F-4 in [CASE_STUDY.md](./CASE_STUDY.md), checked against the current repository files.  
**Audit type:** Static review. The pipeline was not executed, and the Bronze input files are not present in the repository listing. Findings about actual data values, runtime, model-download behavior in AeroMart's network, or production cost are identified as conditional or unverified rather than measured.

## Top five immediate pipeline improvements, in priority order

The case study instead asks for review of an inherited pipeline and explicitly says to document the vector-index/search gap. This ranking therefore prioritizes defects in the pipeline that exists today. ### Separate architectural gap: D-2

**D-2 remains a valid architectural gap, but is not an immediate inherited-pipeline code defect.** [load_gold.py:27–33](./load_gold.py) writes embeddings to Parquet; the brief asks the reviewer to document that no production vector index/query service is established and what would be required to close the gap. Whether AeroMart should build that downstream capability, and which backend it should use, requires a separate product/architecture decision. Do not assume Qdrant or any other store is required to complete this review milestone.

There are now uncommitted Qdrant-related working-tree changes from an earlier iteration ([qdrant_index.py](./qdrant_index.py), [qdrant_search.py](./qdrant_search.py), and ID-generation changes in [transformation.py](./transformation.py)). They have not been integration-tested or committed and should be treated as a proposal, not an accepted D-2 resolution or a required part of this revised top-five plan. No claim is made that they form a production-ready index/search service.

## Severity guide

- **High:** Can block the product objective, create material data loss, or allow serious integrity/privacy/operational failure if deployed as-is.
- **Medium:** Material quality, performance, privacy, or reproducibility risk that warrants a defined control before production.
- **Low:** Limited immediate impact, maintainability/documentation issue, or an optimization whose benefit depends on workload.

### Why this ranking differs from the original

Severity describes potential consequence; priority chooses what to fix first within the inherited pipeline's scope. C-2 and C-10 concern correctness and silent data loss; B-3 is an existing Spark cost risk and now ranks third; B-1 is an existing embedding-stage throughput risk; A-5 is a concrete determinism issue. D-2 is still important to the broader semantic-search product, but the case study asks us to document the gap rather than choose and implement a vector database. D-1 is conditional on offline/cache state and should be verified before it outranks demonstrated pipeline issues.

The ranking is provisional because there are no production volumes, Spark plans, run times, capacity limits, or measured data-quality rates. If profiling shows B-3 breaches an operating window, increase its priority. Estimated effort above is relative planning guidance, not a commitment or benchmark.

## Review limitations and follow-up

- The audit verifies repository code and saved notebook content only; it does not establish observed data frequencies, measured runtime, model-serialization behavior, production resource utilization, or actual personal-data prevalence.
- The notebook's saved outputs show earlier execution results; in particular, the `spark.stop()` cell has no execution count while downstream cells do. Static inspection therefore supports the top-to-bottom failure finding, but this audit did not execute the notebook.
- The C-4 entity example is visible in saved demo output; it does not establish the frequency or range of markup/encoding issues across the full source.
- The exact overlap in A-8 cannot be calculated because the Bronze inputs are absent and the notebook does not join the two 200-row samples.
- For disconnected on-prem deployment, provision the pinned model artifact locally and test startup with network access disabled before declaring D-1 resolved.
- The top five are priority recommendations, not the only issues. All 46 case-study checklist IDs above have a status, evidence, severity, and AeroMart impact.
